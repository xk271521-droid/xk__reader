# PDF 文字选区引擎隔离测试

## 项目目标

先用同一份论文、同一组动作比较两条免费技术路线，再决定是否值得迁移正式阅读器：

- PDF.js 原生文字层：作为浏览器原生选区基准，不代表当前正式阅读器。
- PDFium/WASM：使用 EmbedPDF v2.15.0 的稳定版作为候选基准。

## 隔离边界

本轮只增加 `/poc/pdf-selection-engine-test.html` 测试入口。

当前默认测试样本为 `frontend/public/poc/sthelar-selection-test.pdf`，来源是用户指定的 STHELAR 论文副本，仅供本地隔离测试。

- 不修改正式阅读器选区逻辑。
- 不修改标注、选区浮窗、跨双栏控制。
- 不修改后端、数据库、用户文献和部署入口。
- 不把候选库加入正式依赖；测试页从 jsDelivr 临时加载固定版本。

## 核心假设

问题不只是“免费或付费”，而是文字定位、字符命中、阅读顺序和选区状态机是否成熟。PDFium/WASM 如果在双栏、反向拖动、行末和空白处收尾时明显更稳定，就值得进一步验证如何接回现有标注与浮窗；如果没有显著提升，就不迁移。

## 统一测试用例

每个引擎用同一份 PDF、相同缩放比例，重复以下动作至少 3 次：

1. 单词：只选中一个英文单词。
2. 句子：从句首拖到句号，不多一个字符、不少一个字符。
3. 反向拖动：从句尾向句首拖动。
4. 跨行：精确选择连续 3 行。
5. 双栏边界：在左栏内向下选取，不跳入右栏。
6. 断词：选取带行末连字符的单词。
7. 引用/上标：选择正文附近带上标引用的短句。
8. 空白收尾：鼠标在文字右侧或下方空白处松开。

记录结果：准确、多选、少选、跳栏或失败。缩放建议至少测试 100%、150% 和 200% 附近。

## 判定标准

候选方案只有同时满足以下条件才进入下一阶段：

- 双栏跳选率明显低于 PDF.js 原生基准和当前正式阅读器。
- 反向拖动、行末收尾、空白收尾没有明显退化。
- 能稳定取得选中文本和矩形范围，具备接回标注与浮窗的接口条件。
- 保持免费、可自托管，许可证允许项目使用。

## 方案与问题记录

- 否决“直接恢复 PDF.js 原生选区”：过去体验已经证明它不满足目标，本轮只把它作为基准。
- 暂不购买商业 SDK：先测免费 PDFium/WASM 的能力上限，不把价格当成准确率的唯一解释。
- 暂不直接替换正式选区：引擎准确率与标注/浮窗/跨栏集成是两个阶段，必须先验证前者。
- GitHub 源码下载曾出现超时，因此隔离测试改用 npm 已发布的固定 CDN 版本；正式接入前仍需改为本地托管并完成许可证复核。

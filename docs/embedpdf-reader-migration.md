# EmbedPDF/PDFium 阅读器迁移项目书

## 目标

在不改变 XK 阅读整体页面风格和核心业务能力的前提下，将 PDF 渲染、文字选区、标准批注和批注编辑底层迁移到 EmbedPDF v2.15.0 / PDFium WASM。

正式版本必须本地打包运行，不依赖 EmbedPDF 或 CloudPDF 服务器。

## 已确认决策

- 保留 XK 阅读现有浅色、紧凑界面，不嵌入 EmbedPDF 的完整深色工具栏。
- 顶部采用“一级分类 + 二级工具”的工具集布局，避免所有按钮挤在一行。
- 原有功能是最低功能线，只能替换实现，不能删除。
- 选中文字后继续显示 XK 阅读选区浮窗。
- 截图后的翻译、钉住、下载、插入笔记、AI 解读浮窗继续保留。
- 旧 PDF 批注无需迁移；正式切换时可以清空旧文字、手写和图形批注数据。
- 用户再次确认：旧批注实现或数据与新链路冲突时直接删除，以新链路为准；但新阅读器切为默认之前仍保留旧阅读器作为临时回退。
- 文献、阅读记录、侧边笔记、截图资源、AI 聊天和全文翻译数据不得清除。
- 网页版和桌面端共用同一套前端核心和后端数据。

## 界面结构

顶部第一行显示分类：阅读、批注、图形、插入。右侧固定显示撤销/重做、搜索、页码、缩放和下载。

顶部第二行显示当前分类的工具，工具栏总高度固定，切换分类时不推动论文页面上下跳动。

选中文字后显示快捷浮窗：

- 四种常用颜色
- 高亮
- 下划线
- 波浪线
- AI 解读
- 添加笔记
- 更多：删除线、复制、翻译、评论、链接

选区文本、矩形和浮窗位置全部来自 EmbedPDF Selection capability；AI、翻译和笔记动作仍调用 XK 阅读业务接口。

## 当前数据问题

现有 PDF 批注被拆分为三套数据：

- `annotations_v2`：仅支持高亮、下划线和波浪线，依赖字符下标和自定义矩形。
- `paper_ink_annotations`：单独保存手写点；创建失败仅在当前内存标记未同步，刷新后丢失。
- `paper_shape_annotations`：单独保存文字、箭头、矩形、圆形和编号。

当前接口按单次动作立即请求；不存在统一批量同步、持久化离线队列、服务器修订号或跨设备冲突处理。部分前端异常会被静默忽略。

## 新数据模型

新增统一表 `paper_pdf_annotations`，每条记录保存一个 EmbedPDF 批注对象：

| 字段 | 用途 |
|---|---|
| `id` | 数据库主键 |
| `uid` | 客户端生成的稳定 UUID，同一批注跨设备不变化 |
| `user_id` / `paper_id` | 账号和文献归属 |
| `page_index` | EmbedPDF 使用的 0 起始页码 |
| `annotation_type` | highlight、ink、square、text 等类型 |
| `payload_json` | 完整、经过校验的 EmbedPDF 批注对象 |
| `version` | 单条批注乐观并发版本 |
| `created_at` / `updated_at` | 创建和更新时间 |
| `deleted_at` | 删除墓碑，用于多设备同步删除 |

新增 `paper_annotation_states`：每个用户、每篇文献一条状态，保存服务器递增 `revision` 和更新时间。

## API 契约

- `GET /api/papers/{paper_id}/pdf-annotations`
  - 返回当前 revision、schema version 和未删除批注。
- `POST /api/papers/{paper_id}/pdf-annotations/sync`
  - 一次提交多个 upsert 和 delete 操作。
  - 请求携带客户端已知 revision。
  - 返回服务器新 revision、已确认操作和必要的冲突结果。
- `DELETE /api/papers/{paper_id}/pdf-annotations`
  - 只清空当前用户、当前文献的新 PDF 批注。
- 管理迁移脚本
  - 正式切换时清空旧三套 PDF 批注数据，但不删除表结构。
  - `backend/scripts/clear_legacy_pdf_annotations.py` 默认只显示待删数量；必须明确指定用户范围或 `--all-users`，并输入固定确认短语后才会真正删除。

服务端必须验证文献所有权、批注类型、页码、单条 JSON 大小、批量数量和字符串长度，不接受任意无限 JSON。

## 前端保存机制

1. 打开论文时先载入服务器批注，并注入 EmbedPDF。
2. 创建、更新、移动、改色和删除通过 EmbedPDF 事件进入本地操作队列。
3. 界面立即乐观更新，不等待网络。
4. 500ms 合并连续操作后批量同步。
5. 同步失败写入 IndexedDB 持久化队列，不能只放 React 内存。
6. 网络恢复、重新登录或再次打开论文时自动重试。
7. 工具栏显示“已保存 / 保存中 / 未同步”，失败可手动重试。
8. 多端同时编辑采用单条版本检查；冲突时服务器保留最新有效版本并回传状态。

## 导出

- 带批注 PDF：优先使用 EmbedPDF Export capability 在本地生成，保持标准 PDF 批注。
- Word：后端读取统一批注表，输出页码、引文、评论和批注类型。
- Markdown/BibTeX：保持现有业务格式；引用信息不与 PDF 批注表混用。
- 原始 PDF 默认不覆盖，只生成新的带批注副本。

## 迁移阶段

1. 本地化依赖和 WASM/Worker/字体，断网验证。
2. 新增统一数据表、批量同步接口和后端测试。
3. 新增前端 EmbedPDF 适配层和持久化队列。
4. 接入阅读、选区和选区浮窗。
5. 接入文字批注、画笔和图形。
6. 接回截图、AI、笔记、全文翻译和导出。
7. 通过功能开关并行验证新旧阅读器。
8. 验收后清空旧批注数据并切换默认阅读器。
9. 保留旧表和旧代码一个回退周期，稳定后再清理。

## 否决与风险记录

- 不直接嵌入完整 EmbedPDF Snippet UI：会破坏 XK 阅读界面和业务整合。
- 不在正式阅读器中长期并行运行两套选区状态机：会发生事件和坐标冲突。
- 不让 Pan 插件自行判断触控设备：EmbedPDF 2.15.0 运行时默认值实际为 `mobile`，可触控电脑会把箭头工具静默变成 `grab` 平移模式，导致文字拖选失效。正式配置固定 `defaultMode: never`，并显式把文字选择绑定到 `pointerMode`。
- 不继续维护三套独立批注表：难以支持统一撤销、同步和标准 PDF 批注。
- 不为每个指针移动发送请求：必须按完整批注事件批量保存。
- 不把整份修改后的 PDF 作为每次自动保存的数据：体积大、冲突难处理；数据库保存结构化批注，导出时再生成 PDF。
- EmbedPDF v2.15.0 固定版本上线，升级必须重新运行选区和批注回归测试。
- 不直接依赖 `@embedpdf/pdfium/pdfium.wasm?url`：Vite 8 开发模式会把 Worker 请求解析成 JavaScript 包装地址。项目固定复制并校验 `/vendor/embedpdf/pdfium-2.15.0.wasm`，网页、构建产物和桌面本地服务器共用此路径。
- EmbedPDF 2.15.0 Worker 在当前 Vite 8 网页环境 40 秒内仍无法完成初始化；网页默认使用已通过真实渲染和拖选测试的本地 direct 模式。
- 隔离对比页使用完整 Snippet 时会加载可选默认印章资源；正式阅读器采用 Headless 插件且不注册 stamp 插件，因此正式链路不依赖该 CDN。

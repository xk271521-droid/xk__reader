# XK 阅读本地运行

## 目标

在远端服务器不可用的情况下，将 XK 阅读作为单机应用运行：后端连接本机 MySQL，网页端和桌面端请求本机后端，上传文件保存在本地。

## 当前状态

- 本机 MySQL80 正在运行，数据库名为 `xk_reader`。
- 用户已清理业务数据，仅保留 `ai_providers` 中的两个 API 配置。
- 代码模型比本地表结构新增 6 张表；后端启动时的 schema sync 会使用 `checkfirst` 创建它们，并补齐已登记的兼容字段。
- 本地模式禁止上传镜像和 OSS，避免访问已退役服务器或遗留存储配置。

## 本地模式约定

- `backend/.env` 保留原有连接凭据，不直接修改。
- `backend/start-standalone-local.ps1` 仅为当前进程切换本机 MySQL `127.0.0.1:3306`，不写入密钥。
- 前端开发服务器固定监听 `http://127.0.0.1:5173`，并开启 Vite `strictPort`；5173 被占用时直接失败，不会自动跳到 5174、5175。
- 后端固定监听 `http://127.0.0.1:8000`，前端开发服务器只将 `/api` 和 `/uploads` 代理到该端口。
- 本机桌面调试使用 `paper-reader-desktop/start-local-desktop.ps1`；它以环境覆盖将 Electron 代理指向同一地址，不更改打包默认配置。

## 问题归档

- 2026-09-24：开发启动脚本曾误设置 `XK_READER_STANDALONE=true`，导致开发后端新建/使用 `backend/data/xk-reader.sqlite3` 空库，登录显示“账号或密码错误”。原有 `MySQL80` 的 `xk_reader` 未删除，核对仍有 3 个用户、19 篇文献，目标手机号账号存在。开发脚本已改为 `XK_READER_USE_LOCAL_DATABASE=true`，继续连接本机 MySQL；打包独立版仍单独使用 SQLite。

- 本地启动包装脚本不能检查 `$LASTEXITCODE`：其调用的后台启动命令不保证重置该值，会造成错误的失败退出。已移除此检查，实际状态统一以健康接口验证。
- 旧 SSH 隧道 URL 使用的账号不具备本机 MySQL 权限。本地开发模式使用 `.env` 中的连接凭据并只将主机与端口改写为 `127.0.0.1:3306`；不会修改账户或密码。打包独立版另用 SQLite。
- 后端启动时报告两个 SQLAlchemy relationship 重叠警告，当前不影响本地服务或测试；后续整理模型关系时应补充 `back_populates` 或 `overlaps` 声明。

## 已知限制

- 本地库当前仍有 2 个用户记录；未读取或改写密码。若不记得账号密码，重置流程仍需要可用的短信或邮件服务。
- AI、短信、邮件等能力仍依赖各自的第三方服务；本地运行不等于离线运行。
- 预期的已安装 `XK 阅读.exe` 当前不在项目说明记录的位置；本地桌面端先使用开发启动脚本，之后可按需重新打包安装器。

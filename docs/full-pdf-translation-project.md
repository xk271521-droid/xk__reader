# 全文 PDF 翻译项目书

## 状态

- 状态：首个可部署版本已完成，等待独立翻译运行时部署与真实论文验收
- 创建日期：2026-08-09
- 负责人：XK 阅读项目
- 适用范围：网页版核心与共享后端；桌面端在重新打包网页版后自动获得相同能力。

## 产品目标

提供接近“小绿鲸”截图的全文翻译体验：用户保留原始 PDF，同时获得一份版式尽量保持一致的中文译文 PDF，并可在阅读器中进行双屏关联阅读。

“版式保留全文翻译”指标题、双栏、图片、表格、公式和页码仍保持在原来的相对位置；它不是把提取出的纯文字另排成网页。

## 已确认的技术决策

| 层级 | 技术 | 职责 |
| --- | --- | --- |
| 全文翻译主引擎 | PDFMathTranslate / BabelDOC | 原 PDF 转为中文译文 PDF 或双语 PDF，尽量保留学术论文版式。 |
| 复杂 PDF 解析回退 | MinerU（第二阶段） | 用于定位扫描件、复杂双栏、表格或公式的结构问题；它不能单独生成可比拟的保版译文 PDF，因此首版不自动切换。 |
| 翻译质量 | SiliconFlow 四模型优先级 + 可选术语规则 | 默认按 GLM-4-9B-0414、Qwen3-8B、GLM-Z1-9B-0414、Hunyuan-MT-7B 依次选择；保护基因名、药名、公式、DOI、作者和引用编号。 |
| 阅读展示 | 现有 PDFium/WASM | 显示原 PDF 与已生成译文 PDF，提供页码/滚动关联；不参与译文生成。 |

本期不接入 OpenDataLoader PDF 与 Unlimited-OCR。它们分别与 MinerU 的解析职责重叠、或只服务于极差扫描件，均不直接生成版式保留译文 PDF。

## 核心产品规则

1. 一篇论文默认只创建一次全文翻译任务。
2. 成功生成的译文 PDF 是该论文的持久化产物；再次打开时直接读取，不重复调用解析或翻译服务。
3. 只有用户点击“重新翻译”后才允许创建新任务；旧译文在新译文成功前保留，成功后由新版本替代。
4. 任务失败、取消或配置缺失时不自动反复重试；用户需要明确点击“重新翻译”。
5. 当前缓存记录原 PDF 的文件哈希、译文文件哈希、译文版本以及 PDFMathTranslate 运行快照。翻译服务或术语配置变化只在用户明确重新翻译后生效。

## 不做什么

- 不再以浏览器 PDF.js 文字切块作为全文翻译的源数据。
- 不把全文翻译结果伪装为可编辑的原 PDF；批注仍以原 PDF 为准。
- 不在第一版同时运行多个主解析器；模型切换只在价格保护、限流、鉴权、超时或明确的模型级失败时发生，并记录切换原因。
- 不因为用户打开论文、切换页面或刷新浏览器而触发重新翻译。

## 目标用户流程

1. 用户打开论文并点击“全文翻译”。
2. 若该论文存在完成的译文 PDF，直接进入译文阅读，不发起新任务。
3. 若不存在，用户确认后后台生成译文 PDF，并在任务中心显示进度。
4. 完成后保存产物路径、文件哈希、生成配置快照和完成时间。
5. 用户在原文/译文双屏中阅读；需要更新时主动点击“重新翻译”。

## 质量验收线

- 英文双栏论文的标题、正文阅读顺序和页码与原文一致。
- 公式、DOI、作者、图号、表号和引用编号不被普通文本翻译破坏。
- 已完成论文重复打开时不创建任务、不消耗翻译额度，且返回同一保存产物。
- 点击“重新翻译”才创建新版本；若新版本失败，旧版本仍可打开。
- 扫描件或复杂表格失败时给出明确错误/回退信息，不输出看似完成但错乱的译文。

## 已否决方案与原因

- 旧版“浏览器文字块 + 逐段翻译 + 页面覆盖层”：无法可靠保留复杂学术 PDF 的版式，已停止使用。
- PDFMathTranslate 之外再自研整套 PDF 版式重建：成本高、错误面大，优先复用成熟引擎。
- 直接接入 Unlimited-OCR：需要额外 GPU 资源，且不解决版式翻译本身。

## 2026-08-09 实施记录

- 后端任务已改为只读取已上传的原始 PDF，不再接收浏览器提取的 `pages` 作为全文翻译输入。
- 新增 PDFMathTranslate 命令运行器：临时目录执行、超时和输出 PDF 校验、原子保存、本地/镜像/OSS 持久化，以及论文删除时的产物清理。
- 同一论文已有译文 PDF 时，启动接口直接返回缓存；仅 `retranslate` 接口创建新版本。重译失败或任务超时时，旧译文保持可读。
- 前端已改为 PDFium/WASM 双屏：左原文、右译文 PDF、按页联动、下载和显式“重新翻译”。旧的 HTML 段落重排阅读器已退役。
- 已知部署前置条件：生产后端仍是 Python 3.10，PDFMathTranslate 必须安装在独立 Python 3.11/3.12 环境，并将其 `pdf2zh` 路径写入 `PDFMATHTRANSLATE_COMMAND`；功能开关在通过真实论文验收前保持关闭。

### 真实运行验收补充（2026-08-09）

- 本机独立运行环境已安装并验证 `pdf2zh==1.9.11`。该版本需要固定 `tencentcloud-sdk-python-tmt==3.1.121`；较新的 SDK 缺少它导入的类型。
- BabelDOC 0.2.33 与 NumPy 2 的已删除二进制接口不兼容。项目通过独立的 `scripts/pdfmathtranslate_entry.py` 做窄范围兼容，不污染 API 进程；运行超时时会清理其整个子进程树。
- 真实 9 页英文双栏论文的第 1 页验证：GLM 组合仅翻译标题和少量短文本（中文覆盖 57 个字），已判定为不合格；DeepSeek `deepseek-chat` + BabelDOC 单线程完成 15 个正文段落，中文覆盖 976 个字，并保留双栏和页面版式。因此首版默认服务固定为 DeepSeek，不做静默服务切换。
- 新增英文→中文正文覆盖质检：原文正文较多而产物几乎没有中文时，任务视为失败，不保存半成品；若已有旧译文，旧译文继续可读。

### 全局 AI 厂商联动（2026-08-09）

- 全文翻译只使用 AI 厂商配置中的 SiliconFlow 接口和密钥，模型由全文翻译专用优先级控制：`THUDM/GLM-4-9B-0414` → `Qwen/Qwen3-8B` → `THUDM/GLM-Z1-9B-0414` → `tencent/Hunyuan-MT-7B`。未配置 SiliconFlow 时必须报配置错误，不得回退到全局 DeepSeek/GLM；SiliconFlow 配置不需要成为全局“已启用”厂商，全局启用的 DeepSeek/GLM 继续服务 AI 精读和边读边问。
- SiliconFlow 卡片在配置页标为“翻译专用”，不提供全局启用开关；即使旧数据曾将它设为全局启用，读取配置时也会自动迁回翻译专用状态。
- 已归档一个启动失败 Bug：`pdf2zh 1.9.11` 包装入口不接受 BabelDOC 的 `--no-dual`，此前导致任务只显示命令用法便失败；现已过滤该参数，输出优先取单语 `.mono.pdf`。
- 任务保存厂商 ID、名称、地址和模型快照（绝不保存明文密钥）。用户随后切换全局厂商不会重译已保存论文；下一次主动重新翻译才采用新选择。
- 已识别旧腾讯机器翻译：它仅保留给划词翻译的“腾讯”选项，并有一段不再被新任务调度器调用的浏览器分段翻译旧代码；保版全文 PDF 不使用腾讯机器翻译。
- 兼容已排队的旧任务：早于“厂商快照”上线、因而没有 `provider_id` 的任务，执行时自动绑定用户当前启用的全局厂商并记录快照；已经失败的任务不会暗中重跑，仍须用户明确点击“重新翻译”，避免产生未确认的翻译费用。
- 速度与进度：保版翻译需要先解析页面结构、并发翻译段落，再重新排版生成 PDF；它不等同于一次短文本翻译。模型请求层通过有限重试、四模型兜底和分段缓存减少第 2 个瓶颈；PDF 解析、布局分析和重排是第 1 个瓶颈，只能通过并发、跳过不必要的输出和真实阶段进度优化，不能完全消除。当前运行任务保持其启动时的参数，不中途无故终止重启。
- 成本防护修正：文献速读在首次打开某篇论文时自动创建一次，并以每篇论文唯一记录持久化；后续打开只读取缓存，成功、排队和失败均不会重复创建。AI 目录在首次切到“目录”时遵循同一规则；失败后仅用户明确点击“重试”才会再次调用。划词翻译仍以用户实际选词作为触发条件。
- 术语质量反馈：用户实测 Hunyuan-MT-7B 的学术专业术语不如 GLM-4-9B-0414 和 Qwen3-8B，故 Hunyuan 降为第四顺位，仅作为兜底，不作为默认全文翻译模型。

### 专注阅读布局（2026-08-09）

- 全文译文阅读采用临时“专注阅读壳层”：打开译文时隐藏站点全局顶栏，阅读器铺满整个视口。
- 阅读器内仍保留返回、双屏联动、重新翻译和下载控制；返回原文后恢复普通工作区。
 
- 2026-08-09: Full translation toolbar is now a compact 44px square-corner strip. Linked reading maps each side's real viewport scroll progress to the other document and suppresses short-lived programmatic callbacks, preventing visible lag and feedback loops.
- 2026-08-12: Added a translation-only reading mode in the full-translation toolbar. It removes the original-PDF pane and expands the translated PDF across the reading surface; the same control restores side-by-side comparison without opening a second page.

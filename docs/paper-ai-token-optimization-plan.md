# 论文 AI Token 优化计划书

## 文档状态

- 状态：方案草案，尚未进入编码阶段
- 日期：2026-08-08
- 适用范围：网页版及共用后端
- 当前基线：每次 AI 请求使用当前论文完整正文，不携带旧聊天记录

## 目标

在不明显降低论文问答准确性的前提下，降低长论文重复发送和处理全文带来的输入 token、延迟和费用。

准确性优先级高于节省 token。任何检索结果不可靠的情况，都必须能够自动扩大上下文或回退到全文。

## 不变的产品约束

1. 每篇论文按 `paper_id` 隔离，不能混用其他论文内容。
2. AI 精读和直接提问继续共用同一个问答服务。
3. AI 精读发送选中文字；直接提问发送用户问题。
4. 旧聊天记录只用于界面显示，不自动作为模型上下文。
5. 选词翻译与全文 AI 问答保持独立。
6. 本阶段只开发网页版和共用后端，不打包 Electron 桌面端。

## 回答知识边界

论文内容不是唯一的回答来源。系统需要区分但不割裂两类信息：

1. **论文事实**：作者在本文中提出、报告或证明的内容。必须尽量附页码和章节，不能用模型推测替代论文结论。
2. **通用知识与推理**：模型对概念、方法背景、常见机制、局限和跨领域关系的解释。可以帮助用户理解，但必须明确标注为模型补充或合理推断，不能伪装成论文原文。

建议的回答结构：

```text
论文中明确说明：…… [第 N 页]

结合通用知识的解释：……

与本文的关系 / 仍需核实的部分：……
```

路由规则：

- 询问本文具体实验、数字、作者观点或结论：以论文证据为主。
- 询问概念定义、原理、背景知识、常见做法或潜在原因：允许模型结合通用知识解释，并关联到论文。
- 同时涉及论文和背景知识：同时检索论文证据并生成明确分层的回答。
- 涉及最新事实、临床/医疗建议、政策或用户明确要求外部来源：不能只依赖模型内部知识；后续应启用联网检索并提供来源。

## 总体路线

```text
全文版基线
  -> 固定前缀与缓存观测
  -> 论文分块与页码索引
  -> 关键词 + 向量混合检索
  -> 重排与证据质量判断
  -> 自动扩大范围或全文回退
  -> 基于真实问题集校准
```

## 阶段一：全文基线与缓存观测

先完成并验证当前全文版，不在此阶段加入检索。

- 系统提示、论文标题、带页码全文保持稳定顺序。
- 当前选中文字或问题放在动态区域。
- 记录每次请求的论文 token 数、输入 token、输出 token、耗时和供应商缓存命中信息（如果供应商返回）。
- 记录选词精读和直接提问的请求类型，但不记录旧聊天作为模型上下文。

目的：获得真实基线，判断哪些论文和问题真正产生高 token 成本。

## 阶段二：论文分块与检索索引

### 分块原则

- 优先按 PDF 页码、章节标题、段落边界切块。
- 不在句子中间强行截断。
- 每个块保存 `paper_id`、页码、章节、文本、顺序号。
- 保留相邻块关系，检索命中后可补充前后块。
- 表格、图注、参考文献暂时作为独立块，不与正文混在一起。

### 父子块与论文证据

检索使用较小的子块，以便准确找到用户所问的方法、术语或结果；模型回答使用命中子块所属的较大父块（完整段落或章节片段）以及相邻块。

```text
小块负责“找准位置”
大块负责“提供完整语义”
```

这避免模型只看到一句孤立文字而误解条件、限定语、图表解释或跨页关系。

### 检索顺序

第一版采用混合检索：

1. 关键词/BM25：适合方法名、缩写、基因名、数据集名等精确术语。
2. 向量检索：适合用户换一种说法提问的语义匹配。
3. 使用 RRF 等排名融合方法合并结果。
4. 需要时再增加轻量重排模型。

暂不引入 GraphRAG、复杂知识图谱或滚动摘要。它们适合多篇论文和全局知识库，不是单篇论文第一版的必要条件。

## 阶段三：自动场景路由

路由由代码自动完成，用户不需要手动选择模式。

### 全文场景

- 询问整篇论文的贡献、研究问题、方法总览、局限、结论或全部实验结果。
- 问题包含“全文、整体、主要、所有、总结、贡献、局限”等全局意图。
- 用户问题无法定位到具体章节或术语。

### 检索场景

- AI 精读已提供选中文字和页码。
- 询问某个方法、变量、实验设置、结果或术语。
- 问题可以由一个章节或少量相关段落回答。

### AI 精读路径

用户选中原文后，选区本身是最强的定位线索。默认上下文按以下顺序构建：

```text
选中文字
  + 同页前后段落
  + 所在章节
  + 全文中同一术语、方法或结论的关键段落
```

选词翻译保持独立；点击“AI 精读”才进入这一问答路径，并自动向右侧阅读聊天发送问题。

### 直接提问路径

直接提问没有原文锚点，需要额外理解问题意图：

- 中文问题与论文中的英文术语、标题、章节名一起检索。
- “本文贡献、整体方法、全部结果、局限、总结”等全局问题直接全文。
- 方法、变量、实验设置、局部结果等具体问题优先检索相关章节。
- 需要跨章节比较时，同时检索相关方法、实验和结果章节。
- 问题含糊、指代不明或无法定位时，扩大范围或直接全文。
- “刚才那个、这个呢”等可能依赖上轮的追问，不自动拼接历史；界面提示用户是否明确引用上一条问题或回答。

复杂问题可在后续阶段拆成机制、结果、局限等子问题分别检索后合并回答。该能力增加一次处理成本，先只用于明显的多目标问题。

### 自动扩大和回退

```text
局部问题
  -> 选区 + 前后段落
  -> 检索相关块
  -> 补充相邻块或整章
  -> 证据仍不足时使用全文
```

## 阶段四：证据质量判断

“置信度”不是模型提供的绝对百分比，而是多个信号的组合：

- 关键词检索与向量检索是否命中相同或相邻块。
- 第一名与后续结果的相关性差距。
- 问题中的关键术语是否出现在证据中。
- 重排结果是否集中在合理章节。
- 检索到的段落是否覆盖问题中的主要实体和动作。
- 最终回答是否能引用具体页码。

不能只依赖单一余弦相似度阈值。初始阈值只作为可调整配置，必须用真实问题集校准。

### 回答展示与自检

- 论文事实尽量显示页码、章节和可展开的原文依据。
- 回答中的关键事实应能够对应到检索块；若不能对应，则扩大上下文、降级为全文，或明确说明证据不足。
- 回答后可生成少量“继续追问”建议，帮助用户继续阅读；这不等于自动把旧聊天带入下一次模型请求。
- 对高风险或证据冲突的问题，后续可增加一次轻量自检：检查回答是否把推测表述成论文结论。该自检必须可观测，并只在需要时运行，避免无意义地增加 token。

## 图片、表格与公式

论文的重要结论经常位于图注、表格说明和公式附近。分块与回答需要：

- 保存图注、表格标题和页码。
- 将图表说明与相邻正文关联。
- PDF 纯文本提取质量不足时，明确提示，而非假装已经理解图表内容。
- 后续评估是否需要增加表格结构化提取或页面图像理解；这属于独立增强项，不阻塞正文问答上线。

## PDF 解析、翻译与 OCR 候选技术评估

当前的 PyMuPDF 全文提取继续作为轻量、快速的默认基线。更高质量解析器的作用是改善阅读顺序、章节、表格、图注、公式和坐标信息，从而提高分块、检索和页码证据质量；它们本身不直接减少模型 token。

| 候选技术 | 推荐定位 | 当前结论 |
| --- | --- | --- |
| OpenDataLoader PDF | 结构化 PDF 解析候选，输出 Markdown/JSON/坐标 | 值得与当前 PyMuPDF 提取做样本对比；若读取顺序、表格和图注更稳定，可作为复杂 PDF 的解析后备。 |
| MinerU | 学术 PDF 的高质量异步解析候选 | 值得优先评估。适合在论文导入后后台生成 Markdown/JSON、章节和页面结构；不能阻塞用户打开 PDF，且应保留轻量提取回退。 |
| PDFMathTranslate | 保留版式的全文双语翻译增强 | 有助于“全文翻译/双语 PDF”体验，不作为检索与问答的主解析链路。问答仍应优先依据原文与结构化解析结果，避免译文对术语和页码证据造成偏移。 |
| Baidu Unlimited-OCR | 扫描件、图表和复杂页面的视觉 OCR 候选 | 适合作为后续按需视觉后备，不适合第一版默认运行。需要独立 GPU 服务、队列和成本/隐私评估；只有普通文本提取失败或用户明确询问图片、表格时才考虑调用。 |

评估时使用同一批真实论文，比较：

- 正文阅读顺序是否正确。
- 标题、章节、页码、图注和表格说明是否被保留。
- 公式、双栏和扫描 PDF 的错误率。
- 导入耗时、服务器资源、部署复杂度和失败回退。
- 使用结构化结果后，检索版与全文版的问答证据是否更完整。

初步优先级：先评估 MinerU 与 OpenDataLoader PDF；PDFMathTranslate 保持在翻译功能层；Unlimited-OCR 留作扫描件和视觉内容的第二阶段增强。

## 阶段五：评估与上线策略

建立一组真实论文问题，至少覆盖：

- 选词解释。
- 方法理解。
- 实验结果追问。
- 图表和图注问题。
- 贡献、局限和全文问题。
- 含糊追问。

对同一批问题同时运行全文版和检索版，比较：

- 答案是否遗漏关键事实。
- 页码证据是否正确。
- 用户是否需要重新提问。
- 输入 token 和费用。
- 首字节延迟及总响应时间。
- 自动回退比例。

同时保留用户主动标记“有帮助 / 不准确 / 未回答到重点”的反馈入口，将真实失败案例归入评测集，用于调整分块、检索、路由和提示词。

只有当检索版准确性达到全文版可接受水平，并且长论文确实节省 token，才默认启用检索。否则保留全文版。

## 预期效果

- 短论文：继续使用全文，准确性不变，节省有限。
- 长论文局部问题：目标是将模型输入从完整论文缩小到相关章节或若干段落，实际节省比例以测试数据为准。
- 全局问题：继续全文回答，避免检索遗漏跨章节信息。
- 检索失败：自动回退全文，成本增加但不牺牲可用性。
- DeepSeek 缓存命中：可降低重复全文前缀的处理费用，但不能把缓存当作永久会话存储。

## 主要风险

1. PDF 分块破坏表格、图注或跨页语义。
2. 向量检索漏掉专业术语或缩写。
3. 局部问题实际依赖全文背景，却被错误缩小上下文。
4. 供应商缓存命中不稳定。
5. 额外检索和重排本身增加延迟。

对应原则：保留页码和相邻块、同时使用关键词检索、全局问题直接全文、低置信度扩大或回退、所有路由指标可观测。

## 暂不采用的方案

- 不把检索结果当作永远正确的唯一上下文。
- 不删除全文版回退路径。
- 不在第一版引入复杂 GraphRAG。
- 不把旧聊天记录自动拼入模型请求。
- 不用一次性的人工阈值代替真实问题评估。

## 验收标准

1. 选词精读和直接提问仍然按当前论文隔离。
2. 全文场景不会被错误缩小为局部检索。
3. 检索不可靠时能够自动扩大范围或回退全文。
4. 每个检索块能够追溯到论文页码。
5. 记录 token、延迟、检索结果和回退情况。
6. 与全文基线对比后，检索版没有明显增加事实错误或关键证据遗漏。
7. 前端测试、后端测试和生产构建通过。
8. 涉及论文外知识的回答必须与论文事实分层展示，不能把模型补充表述成作者结论。
9. 直接提问支持中文问题到论文英文术语/章节的检索扩展，并能正确处理全局、局部、比较与含糊问题。
10. 选词精读优先携带选区、相邻上下文和所在章节；关键回答可追溯到页码或明确标注证据不足。
